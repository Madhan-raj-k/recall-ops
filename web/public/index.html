Incident response · powered by Hindsight agent memory

The fix for tonight's outage is already in last month's postmortem. RecallOps remembers it.

When an alert fires, RecallOps recalls similar past incidents (root causes, fixes that worked, fixes that failed), reflects over them like a senior SRE, and hands the on-call engineer a ranked plan. Every resolved incident is retained, so the next answer is better.

Try a live triage → Watch it learn GitHub

Demo data is synthetic: 18 past incidents at ShopNova, a fictional e-commerce company. Calls hit real Hindsight Cloud + Groq and take ~10–20 s.

      How memory works here
      
  
      
    
      retain()
      Each postmortem is stored with its real incident timestamp, the incident ID as document_id, and tags like service:payments-api, team:dba. Hindsight extracts facts + entities and links them.
      
    
      recall()
      Every alert runs semantic + keyword + graph + temporal retrieval, reranked and cut to a 2,048-token budget. The top facts (with source incident IDs) ground the LLM.
      
    
      reflect()
      An agentic loop over the whole bank, steered by a mission: cite incident IDs, prefer fixes that worked, warn about fixes that failed.
