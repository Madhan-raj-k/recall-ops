incident workflow

Retain → Recall → Investigate → Recommend → Approve → Verify → Learn.

Submit an incident. The same input is investigated with Memory OFF and Memory ON. Approve a remediation, run it in simulation, verify it, and retain the postmortem to Hindsight. Then submit a related incident and check that memory brings the lesson back.

Demo data: ShopNova is a fictional company and every incident record is synthetic. Remediation is simulated only: nothing is ever executed against real infrastructure.

        how it works
        
  
        Three calls. One memory bank.
        
  
        
    
    
        
      
        retain()
        Each postmortem goes in with its real incident timestamp, the incident ID as document_id, and tags like service:payments-api. Hindsight extracts facts and entities and links them.
        
      
        recall()
        Semantic + keyword + graph + temporal retrieval, reranked and cut to a 2,048-token budget. The top facts, with source incident IDs, ground the LLM.
        
      
        reflect()
        An agentic loop over the whole bank with an SRE mission: cite incidents, prefer fixes that worked, warn about fixes that failed.
